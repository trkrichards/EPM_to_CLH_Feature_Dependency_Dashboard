Why building one feature doesn't move EPM databases to CLH

A database can migrate only when every feature it relies on exists in CLH. Most databases need several.

1Executive summary

    How we counted

    1. Latest data. Built from the refreshed directory (, ).
    2. Counted by database. Each database is counted once. An account with several databases counts once per database.
    3. No customer count yet. We report databases until "customer" has an agreed definition.
    4. Only databases still to be migrated are counted. Excluded: completed migrations, Net New, TTP Cutover, cancellations, Connect, Internal and DirectCourse.
    5. Six missing features. Multi-database (Org Picker), HR Download, Self-registration link, SCORM Uploader, Linked Tests and CK Nursing. Multi-database now uses the updated Org Picker definition, which is why the blocked count fell after the data refresh.

    Why we count databases, not customers

    For EPM, “customer” is a hard thing to define for a few different reasons:

    • A “customer” (one ECR) could have multiple databases if they license our content with different delivery methods. Example: Baptist Health Corbin and a TON of others – this is very common.
    • A “customer” (one or multiple ECRs) could have multiple databases if the health system level licenses some of our content, while one of the hospitals license another curriculum separately. Example: Mount Sinai
    • A “customer” (one ECR) could have multiple databases if they chose to manage the content they license on a per hospital basis, instead of at the health system level. Example: VA
    • A “customer” could consist of multiple databases that are part of a health system. This health system may or may not have multiple ECR IDs. Example: Common Spirit
    • A “customer” could consist of multiple databases loosely tied together as part of a consortium or affiliated network. This is most likely multiple ECR IDs. Example: NEAH, Medstar
    • A “customer” could potentially have more than one of the above going on! Example: Kaiser Permanente

    Truly, I don’t know if there is a way to translate databases into “customers” given all of these nuances (and why we’ve stuck with databases for so long). Also, the number of “customers” on EPM is not going to ever be the same as the number of “customers” on CLH, as we will need to combine EPM databases when we move them to CLH. Example: Fortis Hospitals

    Many EPM databases do not have unique ECR IDs right now. Since the VA is contracted at the national level, there is a singular ECR, but ~170 databases associated with the contract, meaning that we assigned them ECR-ID_a/b/c/etc as a placeholder for the ECR ID since we couldn’t reuse the original. We haven’t yet worked out how to translate all of those into unique ECR IDs or even if this is something we will need to do if we can combine all of these on CLH.
